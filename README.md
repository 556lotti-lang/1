# 一人麻雀道場

AI3人と四人麻雀を打ち、**自分の打牌を1手ずつ採点して「何がダメだったか」を指摘する**練習アプリ。
ブラウザだけで動く（サーバー・ビルド不要）。

## できること

**対局**
- 東風戦 / 半荘 / 1局のみ
- AIの強さは やさしい / ふつう / 強い（既定）。「強い」は良形テンパイへの向かいやすさ、
  統計的な押し引き基準、オーラスの着順意識まで見て打つ
- リーチ・ポン・チー・カン（暗槓/明槓/加槓）・ツモ・ロン
- 赤ドラ3枚、裏ドラ、一発、ダブリー、槍槓、嶺上開花、海底/河底
- フリテン（通常・同巡・リーチ後）、九種九牌、流局時のテンパイ料、本場・供託・連荘
- 符計算と役判定（平和〜国士無双・四暗刻・九蓮宝燈まで。数え役満・複合役満あり）

**検討（このアプリの主目的）**

判定基準は戦術資料「麻雀の上達法と必須スキル」に準拠している（`src/theory.js` に構造化して保持）。

- **押し引き**（第1優先・影響極大）: 真っ向から押してよいのは聴牌時。1向聴は打点・形・巡目から
  許容放銃率を算出（好形高打点なら中盤18%まで、14巡目以降は5%まで）。2向聴以下は即ベタオリ。
  副露手への基準はリーチと分け、守備モデル（3フーロで即／2フーロは7巡目以降／1フーロは10巡目以降）
  を超えるまで過度に警戒しない
- **副露判断**（第2優先）: ①役の確定性 ②打点2翻以上 ③1鳴き原則と残存形（唯一の両面は残す）
  の3原則で「クソ鳴き」を検出
- **牌効率**（第3優先）: 全打牌候補のシャンテン数と受け入れ枚数を比較。6ブロックのままの進行や
  シャンテン戻しを指摘。推奨打牌には必ず根拠（フェーズの評価軸・孤立牌の切り順・
  ブロック整理・染め手の手順のどれに当たるか）を添える
- **リーチ判断**（第4優先）: 先制聴牌の即リーチ優位（5巡目先制で和了率53%・放銃率11%）を基準に判定
- **孤立牌の切り順**（第5優先・影響極小）: 字牌 < 1・9 < 2・8 < 3〜7 の価値序列、
  客風は北→西→南→東。影響が小さい項目であることも明示する
- 和了見逃し、放銃（現物があったか＝回避可能だったか）も記録
- 即時指摘: 1手打つたびに「◎最適 / △受け入れ○枚ロス / ✗シャンテン戻し / 押し引きの基準」を表示
- 終局後レポート: 最適打率・スタッツ（和了率/放銃率/和銃差/副露後成績/平均和了巡目）と目安の比較・
  **失点への影響度順**に並べたミス一覧（その局面の手牌つき）・改善の優先順で並べた総評

**危険度モデル**（`src/danger.js`）

表示する確率は「相手のテンパイ確率 × その相手への放銃率」を全員ぶん合成したもの。
テンパイ確率はリーチなら100%、副露手は巡目と副露数から、門前非リーチは
ダマテンの割合として低めに見積もる。放銃率の部分は統計的な序列をそのまま実装している。現物0% → 字牌4枚目〜1% → ノーチャンス(壁)・中スジ・
字牌2枚見え3〜5% → 表スジ・序盤の外側5%前後 → ワンチャンス・生牌字牌5〜8% → 片スジ・暗刻スジ
8〜10% → 無スジ10〜15%。裏スジ・間四間は加点しない（統計的に無スジと変わらないため）。
例外として「序盤の5切れに対する1・9」のみ危険度を上げる。AIの押し引きも同じモデルで打つ。

**理論ガイド**

資料の内容を7セクション（牌効率と5ブロック理論／副露の3原則／押し引きの統計的基準／危険度の序列／
オーラス条件計算／スタッツによる自己診断／牌譜検討の優先度）に整理して app 内から読める。

**オーラス条件計算（4・5・6の法則）**

最終局では、トップとの点差・本場・供託から「脇からのロン／直撃／ツモ」に必要な打点を自動表示する。

**練習補助**
- アシスト表示: 現在の向聴数、推奨打牌（押し引き状況に応じてベタオリ推奨に切り替わる）、
  受け入れ枚数と内訳、現物マークと牌ごとの推定放銃率
- 卓は実際の雀卓と同じ配置。対面＝上、上家＝左、下家＝右、自分＝下。
  河は席の向きに合わせた形で、上下の席は6枚で折り返して下へ、左右の席は6枚で折り返して
  中央へ伸びる。牌そのものは全員分を読める向きのまま描く
- 他家の手牌は伏せ牌で表示（対面は正面向き、左右は横から見た薄い牌）。中央は局・残り牌・
  本場・供託を出す黒板
- 縦画面ではツモ牌を手牌とは別の段に置き、残り13枚を画面幅いっぱいまで拡大する
  （390px幅で28px、ツモ牌は33px）。手牌は画面下に固定表示で、画面の高さに応じて
  卓側を自動的に圧縮するので、どの端末でも手牌が隠れない
- 他家が聴牌していそうなとき、手牌の各牌に「切ったら当たる確率」を表示する
- どちらもワンタップでオフにでき、本番同様の条件でも打てる

## 使い方

ブラウザで `local.html` を開く。相対パスで JS/CSS を読むため、ローカルでは簡易サーバー経由が確実：

```bash
python3 -m http.server 8000
# → http://localhost:8000/local.html
```

`index.html` は Claude Artifact 用（`<!doctype>`/`<head>` を持たない形式）。中身は `local.html` と同じ構成。

## 構成

```
index.html      Artifact 用エントリ
local.html      ローカル閲覧用エントリ（内容は同じ）
style.css       スタイル（ライト=白木の卓 / ダーク=緑の羅紗）
ui.js           卓の描画・操作・検討レポート画面
src/core.js     牌の表現、シャンテン数、受け入れ計算、和了形の分解
src/tiles.js    牌の絵柄(SVG)。萬子=漢数字＋萬、筒子=丸、索子=竹、字牌=漢字、1索=鳥
src/score.js    役判定・符計算・点数計算
src/game.js     対局進行（UI非依存の async ステートマシン）
src/theory.js   戦術基準データ（押し引き基準・スタッツ目標・危険度序列・条件計算・理論本文）
src/danger.js   危険度モデル（現物/壁/スジ/字牌の見え枚数から推定放銃率を算出）
src/discard.js  推奨打牌エンジン（フェーズ別の評価軸・孤立牌の切り順・ブロック強弱・
                染め手判定・押し引きから「どの牌を切るか」と「その理由」を決める）
src/ai.js       AI（牌効率＋資料準拠の押し引き・副露判断・着順意識）
src/review.js   検討エンジン（1手ごとの採点とミス検出）
tests/          エンジンの検証テスト
```

### シャンテン数の計算について
スート単位の分解表をメモ化し、4グループ（萬/筒/索/字）をDPで合成する方式。
1局面あたり約7µs で、総当たりのリファレンス実装と乱数16000局面で一致を確認済み。

## AIの強さ検証

```bash
node tests/tournament.cjs 400 strong normal   # 強いAI1人 vs ふつう3人を400半荘
```

席順をならしながら平均順位・和了率・放銃率を集計する。400半荘での測定誤差は
平均順位で±0.06、平均点差で±550点ほどあるため、小さな差は判定できない点に注意。

## テスト

```bash
node tests/engine.test.cjs    # 74件: シャンテン/待ち/受け入れ/役/符/点数、
                              #       および戦術基準（条件計算・押し引き・危険度序列・孤立牌序列）
```

`tests/sim.cjs` は AI 同士で多数対局を回し、例外が出ないこと・点棒の合計が常に
100000 に保たれること（供託込み）を確認する。

```bash
node tests/sim.cjs
```

## 出典

判定基準はすべて共有された2つの戦術資料に基づく。`src/theory.js` がその構造化データで、
他のモジュールはすべてここを参照する。基準を変えたい場合は `src/theory.js` を編集すれば
アプリ全体（推奨打牌・検討・AI）に反映される。

**「麻雀の上達法と必須スキル」**（統計的麻雀戦術とAI牌譜解析）
- 押し引きの許容放銃率、守備モデル、危険度序列、スタッツ目標とロードマップ、
  オーラス条件計算（4・5・6の法則）、牌譜検討の優先度

**「麻雀の局の進め方と戦術」**（一局の意思決定フレームワーク）
- 一局のフェーズ（序盤=打点 / 中盤=スピード / 終盤=安全度）
- 最序盤の孤立牌の切り順「2枚切れ字牌 → オタ風 → 孤立1・9 → 役牌 → 孤立2・8 →
  孤立5 → 孤立4・6 → 孤立3・7」
- ブロックの強弱「辺張 < 余剰対子 < 外嵌張 < 内嵌張 < 両嵌 < 雀頭対子 < 両面 < 完成面子」
- 5ブロック理論の数値（一向聴での累計受け入れ 196枚 > 184枚）
- 染め手の枚数基準と撤退ライン、副露者の聴牌率マトリクス、スジの細分化（1・9 < 2・8 < 3・7）

### 2つの資料で記述が違う点

最序盤の孤立牌の切り順について、資料1は「客風 → 役牌 → 老頭牌」、資料2は
「オタ風 → 孤立1・9 → 役牌」としている。アプリは**資料2**を採用した（AI解析で
約9割の配牌において最適解であること、役牌は重なればポンで1翻が確定して速度が
上がることなど、根拠がより具体的に示されているため）。
