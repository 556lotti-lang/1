# Claude Code のサブエージェントとスキル：運用担当者向け解説メモ

## 1. このメモの目的と対象

運用担当者が team を安全に直すための解説です。[C1] などは出典IDです。

## 2. 用語の早見表

| 用語 | 説明 |
|---|---|
| メイン会話 | 利用者が直接やり取りする会話です。 |
| サブエージェント | Claude が作業を任せる（委任する）補助役です[C5]。 |
| スキル | 作業手順をまとめたファイルで、関連する場面で使われます[C16]。 |
| モデル | 回答を作るAIの種類です（opus など）[C10]。 |
| frontmatter | 定義ファイル冒頭の `---` で囲んだ設定欄です。 |
| YAML | 「項目名: 値」の形で設定を書く記法です。 |
| `/〇〇` | 入力欄に打つ「/」で始まる指示です。 |
| ツール | Claude が使う機能です。名前は tools 欄などに書く文字列です[C42]。 |
| Read | ファイルの内容を読みます[C34]。 |
| Write | ファイルを作成または上書きします[C35]。 |
| Edit | ファイルの一部を編集します[C36]。 |
| Glob | パターン（`*` などを使った条件）でファイルを探します[C37]。 |
| Grep | ファイルの中身からパターンを検索します[C38]。 |
| Bash | 自分の環境でシェルコマンド（命令文）を実行します[C39]。 |

## 3. サブエージェントとは

### 3.1 定義ファイルの置き場所

- ユーザー単位：`~/.claude/agents/`（~ はホームフォルダ）。全プロジェクトで使えます[C1]。
- プロジェクト単位：`.claude/agents/`。チームと共有できます[C2]。
- 同名が両方にあれば、プロジェクト側が優先されます[C3]。

team の定義はプロジェクト単位です［進行役確認］。

### 3.2 書き方：name / description / tools / model

```
---
name: planner
description: （前略）最初の段階で使う。（後略）
tools: Read, Glob, Grep, Write
model: opus
---
```
［実物：planner.md］

**name**：重ならない名前で、最大256文字です[C4]。実物は「planner」です。

**description**：必須で[C32]、Claude はこれで自動委任を判断します[C5]。実物は段階を書いています。

**tools**：列挙したツールだけを使えます。書式はカンマ区切りか、YAML のリスト（項目の並べ書き）です[C7]。実物に Edit はありません。macOS・Linux・WSL（基本ソフトの種類など）では、Glob・Grep は既定で外れます[C40]。Bash を書かずに tools に入れれば、そのサブエージェントでは使えます[C41]。

省略すると、サブエージェントに使えるツールをすべて受け継ぎます[C6]。これはメイン会話のツールから一部を除いたもので、裏で動く場合（既定）はさらに減ります[C6]。

**model**：指定できるのは sonnet・opus・haiku・fable の略称、完全なモデルID（正式名）、inherit です[C10]。inherit はメイン会話と同じモデルです[C11]。実物は opus です。

## 4. スキルとは

### 4.1 置き場所

- 個人用：`~/.claude/skills/<スキル名>/SKILL.md`。全プロジェクトで使えます[C13]。
- プロジェクト用：`.claude/skills/<スキル名>/SKILL.md`。そのプロジェクトで使えます[C14]。

### 4.2 SKILL.md の書き方（agent-team の例）

frontmatter の項目はすべて任意で、推奨は description だけです[C15]。

```
---
name: agent-team
description: （前略）「/agent-team」と言われたときに使う。
---
```
［実物：SKILL.md］

**name**：`/` メニュー（`/〇〇` の一覧）に出る呼び出し名で、省略するとフォルダ名になります[C29][C30]。実物はフォルダ名と同じです。

**description**：Claude はこれでスキルを使う場面を判断します[C31]。実物は呼び出す場面を書いています。

Claude の自動判断[C16]か、`/agent-team` の入力[C17]で呼び出されます。

## 5. ツール権限の考え方

結論：ツールは必要な分だけに絞ります[C9]。

- 権限ルールは deny（拒否）→ ask（確認）→ allow（許可）の順に見ます。最初の一致で決まります[C23]。
- 設定ファイルに書く Bash の deny ルールは、サブエージェントにも効きます[C25]。
- 権限モードは承認を求める範囲の設定です[C33]。確認なしで行う範囲は次のとおりです。
  - Manual（default）：読み取りだけ[C45]
  - acceptEdits：読み取り・編集・よく使うファイル操作コマンド[C46]
  - auto mode：すべて（裏で安全確認あり）[C47]
  - bypassPermissions：すべて（隔離した環境専用）[C48]
- 定義でモードを決める permissionMode を省くと、メイン会話のモードを受け継ぎます[C26]。

**要注意**：メイン会話が acceptEdits・auto mode・bypassPermissions なら、サブエージェントも同じモードで動きます。定義の permissionMode は無視されます[C49]。

## 6. 変更が反映されるタイミング

- サブエージェント：通常は数秒で検知され、次の委任から反映されます[C18]。
- 次の3つは再起動が必要です[C19]。
  - agents フォルダを初めて作った場合
  - `--add-dir`（作業フォルダを追加する起動時の指定[C50]）で加えたフォルダのエージェント
  - `--disable-slash-commands`（スキルと `/〇〇` をすべて止める指定[C44]）で起動した場合
- スキル：再起動なしで反映されます。開始時になかった最上位の skills フォルダを作ったら `/reload-skills` が必要です[C21]。

## 7. 運用担当者が次にやること

- description に「いつ使うか」を具体的に書きます[C5][C31]。
- tools は必要最小限にし、名前の綴りも確かめます[C9][C42]。
- 保存後、次の委任や呼び出しで変更が効いたか確かめます[C18][C21]。
