## 3. サブエージェントとは

### 3.1 定義ファイルの置き場所

- ユーザー単位：`~/.claude/agents/`（~ はホームフォルダ）。全プロジェクトで使えます[C1]。
- プロジェクト単位：`.claude/agents/`。チームと共有できます[C2]。
- 同名が両方にあれば、プロジェクト側が優先されます[C3]。

team の定義はプロジェクト単位です［進行役確認］。

### 3.2 書き方：name / description / tools / model

```
---
name: planner
description: （前略）最初の段階で使う。調査や本文作成はしない。
tools: Read, Glob, Grep, Write
model: opus
---
```
［実物：planner.md］

**name**：重ならない名前で、最大256文字です[C4]。実物は「planner」です。

**description**：必須で[C32]、Claude はこれで自動委任を判断します[C5]。実物は使う段階を書いています。

**tools**：指定すると列挙したものだけを使え、書式はカンマ区切りか YAML のリストです[C7]。実物は4つだけで Edit を持ちません。Linux では Glob・Grep は既定で外れますが[C40]、Bash なしで tools に入れれば使えます[C41]。

省略時は公式に2通りの記述があります（要確認）[C6]。
- 項目表：利用可能なツールをすべて受け継ぐ。
- 本文：メイン会話のツールから一部を除いて受け継ぐ。裏で動く場合（既定）はさらに減る。

**model**：sonnet・opus・haiku・fable の略称、完全なモデルID、inherit（メイン会話と同じ[C11]）を指定できます[C10]。省略時は所定の順で選ばれ、最後はメイン会話のモデルです[C12]。実物は opus です。

## 4. スキルとは

### 4.1 置き場所

- 個人用：`~/.claude/skills/<skill-name>/SKILL.md`。全プロジェクトで使えます[C13]。
- プロジェクト用：`.claude/skills/<skill-name>/SKILL.md`。そのプロジェクトで使えます[C14]。
### 4.2 SKILL.md の書き方（agent-team の例）

frontmatter の項目はすべて任意で、推奨は description だけです[C15]。

```
---
name: agent-team
description: （前略）「/agent-team」と言われたときに使う。
---
```
［実物：SKILL.md］

**name**：`/` メニューに出る呼び出し名で、省略するとフォルダ名になります[C29][C30]。実物はフォルダ名と同じです。変えると呼び出し名も変わります[C29]。

**description**：Claude はこれでスキルを使う場面を判断します[C31]。実物は呼び出しのきっかけを書いています。

呼び出しは、Claude の自動判断[C16]と `/agent-team` の明示呼び出し[C17]の2通りです。

## 5. ツール権限の考え方

結論：ツールは必要な分だけに絞ります[C9]。

- 権限ルールは deny（拒否）→ ask（確認）→ allow（許可）の順に見て、最初に一致したもので決まります[C23]。
- deny ルールはツールの使用を防ぎ[C24]、サブエージェントにも効きます[C25]。
- 権限モード（承認を求める範囲の設定[C33]）は、定義の permissionMode を省略するとメイン会話から受け継ぎます[C26]。
- メイン会話が bypassPermissions・acceptEdits・auto mode なら、定義の指定は無視されます[C27]。

Manual モードでは、編集・書き込みと Bash（読み取り専用の一部を除く）は承認が必要です[C22]。他のモードでは変わります[C33]。

## 6. 変更が反映されるタイミング

- サブエージェント：通常は数秒で検知され、次の委任から反映されます[C18]。
- 次の3つは再起動が必要です[C19]。
  - agents フォルダを初めて作った場合
  - 起動時の追加設定 `--add-dir` で加えたフォルダ
  - `/〇〇` を使えなくする起動設定 `--disable-slash-commands` の場合
- スキル：再起動なしで反映されます。開始時になかった skills フォルダを作ったら `/reload-skills` が必要です[C21]。

## 7. 運用担当者が次にやること

- description に「いつ使うか」を具体的に書く[C5][C31]。
- tools は必要最小限にし、名前の綴りも確かめる[C9][C42]。
- 保存後、次の委任や呼び出しで変更が効いたか確かめる[C18][C21]。
