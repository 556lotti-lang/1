# Claude Code のサブエージェントとスキル：運用担当者向け解説メモ

## 1. このメモの目的と対象

非エンジニアの運用担当者向けに、サブエージェントとスキルの仕組みを説明します。
仕様には出典ID（[C1] など）を付けています。

## 2. 用語の早見表

| 用語 | 説明 |
|---|---|
| サブエージェント | メインの Claude が作業を任せる（委任する）補助役です[C5]。 |
| スキル | 作業手順をまとめたファイルで、関連する場面で使われます[C16]。 |
| ツール | Claude が使う機能です。例：Read（読む）・Write（書く）・Edit（直す）・Glob と Grep（探す）・Bash（コマンド＝命令文の実行）。 |
| モデル | 回答を作るAIの種類です（opus など）[C10]。 |
| frontmatter | ファイル冒頭の `---` で囲んだ設定欄です。 |
| YAML | 「項目名: 値」の形で設定を書く記法です。 |
| `/〇〇` | 入力欄に打つ「/」で始まる指示です。 |
| 権限ルール | ツールの使用を許可・確認・拒否する設定です[C23]。 |

## 3. サブエージェントとは

### 3.1 定義ファイルの置き場所

- ユーザー単位：`~/.claude/agents/`（~ はホームフォルダ）。全プロジェクトで使えます[C1]。
- プロジェクト単位：`.claude/agents/`。プロジェクト専用で、チームと共有できます[C2]。
- 同名が両方にあれば、プロジェクト側が優先されます[C3]。

ホームが /root、作業フォルダが /home/user なので［進行役確認］、team の `/home/user/.claude/agents/` はプロジェクト単位です。

### 3.2 書き方：name / description / tools / model

```yaml
---
name: planner
description: エージェントチームの司令塔。（中略）agent-team ワークフローの最初の段階で使う。調査や本文作成はしない。
tools: Read, Glob, Grep, Write
model: opus
---
```
［実物：planner.md］

**name**：他と重ならない名前で、最大256文字です[C4]。実物は「planner」です。

**description**：いつ委任するかの説明で、Claude は自動委任の判断に使います[C5]。実物は使う段階としない作業を書いています。

**tools**：省略すると利用可能なツールを受け継ぎます[C6]（絞られる条件は [要調査]）。指定すると列挙したものだけを使え、書式はカンマ区切りか YAML のリストです[C7]。有効な名前が1つもないと通常は起動に失敗します[C8]。planner は上の4つだけで、Edit を持ちません。

**model**：sonnet・opus・haiku・fable の略称、完全なモデルID（正式名）、inherit を指定できます[C10]。inherit はメイン会話と同じモデルです[C11]。省略すると所定の順序で選ばれ、最後はメイン会話のモデルになります[C12]。実物は planner が opus、researcher が haiku です。

## 4. スキルとは

### 4.1 置き場所

- 個人用：`~/.claude/skills/<skill-name>/SKILL.md`。全プロジェクトで使えます[C13]。
- プロジェクト用：`.claude/skills/<skill-name>/SKILL.md`。そのプロジェクトで使えます[C14]。

agent-team も同じ理由でプロジェクト用です（`/home/user/.claude/skills/agent-team/`）。

### 4.2 SKILL.md の書き方（agent-team の例）

frontmatter の項目はすべて任意で、推奨は description だけです[C15]。

```yaml
---
name: agent-team
description: （前略）「agent-team で〜を作って」「チームで〜を作成して」「/agent-team」と言われたときに使う。
---
```
［実物：SKILL.md］

**name**：実物はフォルダ名と同じです。公式な役割は [要調査] です。

**description**：使う場面を書きます。実物はきっかけの言い回しを並べています。

呼び出し方は、自動（Claude が関連ありと判断）[C16] と、`/agent-team` のような明示呼び出し[C17] の2つです。

## 5. ツール権限の考え方

結論：ツールは必要な分だけに絞るのが推奨です[C9]。

tools は使える道具の範囲を決め[C7]、権限ルールは実行時の許可・確認・拒否を決めます[C23]。サブエージェントがメイン会話の権限ルールを受け継ぐかは [要調査] です。

承認の要否は次のとおりです[C22]（設定による違いは [要調査]）。
- 作業フォルダ内の Read と Grep は承認不要、編集・書き込みは要承認です。
- Bash は組み込みの読み取り専用コマンドを除き、承認が必要です。

権限ルールは deny（拒否）→ ask（確認）→ allow（許可）の順に評価され、最初に一致したものが結果を決めます[C23]。

## 6. 変更が反映されるタイミング

- サブエージェント：通常は数秒で検知され、次の委任から反映されます[C18]。
- 例外として次の3つは再起動が必要です[C19]：agents フォルダを初めて作った場合、起動時の追加設定 `--add-dir` で加えたフォルダのエージェント、`--disable-slash-commands` 付きで起動した場合。
- `/agents` は、Claude への依頼か直接編集を促す案内を出します[C20]。
- スキル：起動したまま反映され、再起動は不要です。開始時になかった skills フォルダを新設したら `/reload-skills` が必要です[C21]。

## 7. 運用担当者が次にやること

- 直すファイルの場所を確かめる（team は /home/user/.claude/ 配下）。
- description に「いつ使うか」を具体的に書く[C5]。
- tools は必要最小限にし、名前の綴りも確かめる[C8][C9]。
- 保存後、次の委任や呼び出しで変更が効いたか確かめる[C18][C21]。
